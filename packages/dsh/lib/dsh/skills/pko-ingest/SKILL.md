# /pko-ingest — 知识摄取

把外部内容摄取进知识库。来源可以是：URL、文件路径、粘贴的文本，或"处理一下 Inbox"。

## 执行步骤

1. **确定来源**
   - **没给来源** → 处理 Inbox：`glob 00-Inbox/*`，列出所有文件（跳过子目录），
     逐个走完步骤 2–7，然后把原件存档并从 Inbox 删除：
     ```
     写 .raw/YYYY-MM-DD-<原名>（原件内容，不修改）
     bash: mv "00-Inbox/<原名>" "90-Archive/已摄取-<原名>"   # 或直接删除原件；保守做法是归档
     ```
     Inbox 为空 → 告知用户并结束。
   - **URL**（http 开头，不以 .md 结尾）→ `web_fetch` 抓取
   - **URL（.md 结尾）** → 直接 `web_fetch`，已是 Markdown
   - **本地文件路径** → `read`
   - **粘贴文本** → 直接使用

2. **保存原始**：把原始内容写到 `.raw/YYYY-MM-DD-<标题>.md`，一字不改。
   `.raw/` 里的文件**摄取后不可修改**（闸门会拦 edit；新文件名可以写）。

3. **判断类型**
   | 类型 | 提取什么 | 目标目录 |
   | --- | --- | --- |
   | 技术文章 / 论文 | 核心论点、关键技术点、我的思考 | `50-Wiki/<主题>.md` |
   | 会议 / 对话记录 | 决策、行动项、关键信息 | `20-Projects/` 或 `30-Areas/` |
   | 工具 / 产品 | 使用场景、优缺点、与现有工具对比 | `40-Resources/how-to/` |
   | 生活信息 | 实用知识点 | `30-Areas/life/<子目录>/` |

4. **蒸馏成页**：拆成 1–3 页，每页一个主题，按 `_templates/wiki-page.md` 的结构写：
   `概述 / 详细内容 / 关键点 / 相关概念 / 参考来源`。

5. **入库**：用 `pko_ingest`（批量）或 `pko_capture`（单页）写入。同一来源重复摄取会被
   contentHash 跳过，不会产生 `-2` 副本。

6. **更新索引**
   - 在 `50-Wiki/index.md` 对应分类下加一行链接
   - 新概念 → 在 `40-Resources/concepts/` 建概念笔记
   - 在对应 `10-Atlas/moc-*.md` 加链接

7. **记录日志 + 更新热缓存**：写入工具会自动追加 `50-Wiki/log.md`；
   `50-Wiki/hot.md` 由 `/pko-wrap-up` 统一重写，这里不用动。

## 摄取质量标准

- 每页必须有「我的理解 / 为什么重要」段落
- 矛盾信息用 `> ⚠️ 待确认：…` 标注，不要擅自取舍
- 提取可执行的行动项
- 至少建立 1 个与已有笔记的双链

## 链接写入规则

写 `[[链接]]` 之前必须确认目标文件真实存在：

1. 先读 `50-Wiki/index.md` 和对应 `10-Atlas/moc-*.md` 拿到已有文件清单
2. 只链接清单里存在的文件，不写死链
3. 相关但还没创建的，用纯文本提及概念，不加 `[[]]`
